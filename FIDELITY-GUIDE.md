## Spec: problem animation page (viz surface) — owned by agent "viz-core"
Layout (see `ref-bubble.png`, `ref-listrev.png`, `ref-twosum.png`):
1. **Header bar** (full width, `--bg2`, bottom border, padding 14px 28px, one row, wraps): breadcrumb `AlgoFlow / Animated problems` (muted, 0.82rem, links to `/`), **title** in cyan 1.3rem bold, then badges: LC number (orange outline), difficulty (uppercase outline: easy green / medium yellow / hard red), technique tag (purple outline). Right side: a green **"Practice now"** button (opens the problem on LeetCode via `https://leetcode.com/problemset/?search=<id>`; for GFG/IB entries search their site name+title) and a **STATUS** select ("— Not set —", In progress, Practice pending, Solved, Needs revision) using `useProgress`/`STATUS_*` from `src/data/storage.ts`. (No "Watch video" — we have no videos.)
2. **Problem card** (full width): small caps label `PROBLEM`, statement 0.88rem/1.75, then an **EXAMPLE 1** box (`--bg3`, rounded, 3px left border) with `Input:` / `Output:` rows whose values are mono chips (`--bg2`, border), then `Constraints:` in mono 0.78rem muted. Show every example the problem has (EXAMPLE 1, EXAMPLE 2 …).
3. **Try examples card**: small caps label; buttons in mono showing `input → output` with the output in green; active one blue-tinted. Below a divider: `Custom:` label, mono text input (max 400px), blue `▶ Run`, red error text.
4. **Two columns** below, `max-width 1380px`, gap 18px: **left column flexible (takes the remaining width)**, **right column fixed 360px**. On ≤ 860px stack them.
   - Left: *control card* (a muted hint line "▸ Prev / Next = step-by-step. Play = auto-advance. Slider = speed.", then buttons Prev · **Play** (blue-tinted, min-width 92px; turns yellow-tinted while playing, label "⏸ Pause") · Next · Reset, speed slider with `Speed … Slow/Fast` label on the right, a 3px progress bar and a `1 / 30` pill); *approach banner* (purple border, gradient from deep navy to purple-navy, big purple icon on the left, `APPROACH` purple caps label, cyan bold title, muted text; shown only on step 0, fades out after); *visualization card* (title with a small icon, legend chips, mono caption such as `nums[] — current state`, then the picture); *variables card* (grid of boxes: tiny caps label, value in cyan mono 1.1rem, flashes green when a value changes); *step logic card* (left-border box coloured by tone; **bold cyan** key words); *step card* at the bottom (bold title, `n / total` pill, thin progress bar, description 0.85rem muted).
   - Right: *code panel* (header `--bg3` with the title muted left and `Copy` + `Java|Python` segmented tabs right; body mono 0.78rem, **line-height ≈ 1.95**, dim line numbers, the active line(s) get a blue 10% background and a 3px blue left border, green when the step is a success), *algorithm card* (numbered circles 20px; the current step's circle is blue-filled and its text bright; below, three small complexity boxes with the value in orange (time) / purple (space)), *why it works* card (small muted paragraph).
5. **Article** below, centred, max-width 920px, rounded 16px card: `How to solve <title>` h2, a meta line (LeetCode id · difficulty · category · Pattern: …), sections "Why the obvious approach is slow" / "The key idea" / "Remember" built from the problem's `approach`, `why`, `algorithm` (write them as readable prose from the existing fields; add optional fields to `ProblemDef` if you need them, defaulting sensibly), and a "More <category> problems" grid of linked cards (animated ones link to `/problem/<slug>`).
6. A round floating **notes** button bottom-right (blue, 52px) opening a small panel with the notes textarea (replaces the inline "My notes" card).
Animation behaviour to reproduce (all from the reference CSS): array cells **60px** (48px ≤ 860px), radius 8, border 2px, mono 1.15rem bold; index labels `[0]` under cells; active/match/secondary states **lift 4px with a coloured glow shadow** (`0 8px 20px` of the state colour at ~27% alpha), `match` plays a pop (scale 1→1.1→1); other states recolour over 0.35s; visited cells fade to 0.65 opacity; **pointer arrows are separate elements that slide horizontally to their cell with a spring easing (`left 0.4s cubic-bezier(0.34,1.56,0.64,1)`)**, a `▼` above or `▲` below the cell with a mono 0.63rem label in the pointer's colour; sorting swaps slide the two cells past each other (FLIP, keep it) with a quick lift/rotate; sorted cells become solid green blocks; the step title turns green on a "found" step and cyan on done; the result banner slides in (0.35s) with a 🎉.
Other pictures to restyle to the reference (CSS in `raw2/viz-core.css`): **linked list** nodes are rounded two-compartment boxes `[value | ›]` 46px tall with a name badge + `↓` above the node, `→` connectors that flash orange/green when a link changes, a dashed `null` terminator; **matrix** cells (`mat-cell`, 6px radius, row/column header labels, state colours incl. a yellow flash when a value changes); **DP table** as a real `<table>` with header row/column and computing/computed/result/path cell states; **stack** as a vertical column with push pop-in animation, popped (red, faded) and top (green) states; **hash map** as wrapping entries `key → value` (cyan key, orange value) with searched (yellow glow), hit (green glow) and added (blue pop) states; **tree** nodes as circles (fill `--bg3`, stroke 2px, states recolour over 0.4s, edges highlight purple) — all inside the scenes already used by our problems (`src/engine/types.ts` Scene kinds: array, list, tree, grid, split, plus `aux` panels). Do not change what problems emit unless needed; restyle the renderers. If you need new optional scene fields (for example `GridScene.variant: 'matrix' | 'table'`), add them additively to `types.ts` and set them in the problem files that need them (a one-line edit per file is allowed for that purpose only).
