## How to import (build-time, committed output)
- Write an idempotent importer under `scripts/import-cheatsheets/<collection>/` (plain Node `.mjs`, with a short `README.md` saying how to re-run it). Its npm dependencies (e.g. `cheerio`/`parse5`, `marked`/`markdown-it`, `highlight.js`, `postcss`) are installed in a **scratch folder outside the project** (e.g. `%TEMP%\cs-import-<collection>`; run `npm install` there, never in the project, and never edit the project's `package.json`/`package-lock.json`). The importer downloads from the live site / GitHub raw into that scratch folder and **writes the result into the project**: `src/content/cheatsheets/<collection>/…` (HTML fragments, `meta.json`, `NOTICE.md`, `LICENSE.txt`) plus `public/fonts/cheatsheets/<collection>/…` for fonts.
- The importer **sanitizes**: no `<script>`, no inline `on*=` handlers, no `javascript:` URLs, no `<iframe>/<object>/<embed>`, no external `<link>/<script>/<img>` fetched at runtime (images: download and ship locally, or drop with a note). Because imported HTML is rendered with `dangerouslySetInnerHTML`, this is a security requirement and the hub agent's check enforces it.
- **Pre-highlight code at import time** (highlight.js in the scratch folder) and ship the theme CSS, so the app has no runtime dependency and no CDN call. **Self-host the fonts** the original uses (download the woff2 files the original's CSS points to into `public/fonts/cheatsheets/<collection>/`, write `@font-face` rules in your CSS). The finished pages must make **no third-party network requests**.
- Load content **lazily**: one chunk per section/page via `import.meta.glob('/src/content/cheatsheets/<collection>/*.html', { query: '?raw', import: 'default' })` (do not statically import big content into the main bundle).
- **Scope all CSS** under one wrapper class per collection (`.cs-pi`, `.cs-pg`, `.cs-to`). Rewrite `:root`, `html`, `body`, `*` selectors from the original to that wrapper (custom properties can live on the wrapper). Nothing may leak into the rest of the app; check an existing page (e.g. `/` and `/problem/912-bubble-sort`) looks unchanged after your CSS is loaded. Import your CSS from your own component file (e.g. `import '../../styles-cs-pattern-index.css'`). Do not edit `main.tsx`.
- Keep **behaviour** like the original, but implement it in React/TypeScript yourself (read the original's inline JS to learn what it does): copy-to-clipboard buttons, search/filter, scroll-spy highlighting of the active sidebar link, mobile menu toggle, smooth anchor scrolling, `#hash` deep links (our router is `BrowserRouter`: handle `location.hash` yourself on mount and on `hashchange`).
- **Fidelity**: the viewer must look like the original at desktop width and be usable on a phone (no sideways page scroll). Compare screenshots of the original and of ours side by side and iterate. Content must be **complete**: the importer prints a parity report (counts of sections, headings, tables, code blocks, links, rows vs the source) and your check script asserts the same numbers.
